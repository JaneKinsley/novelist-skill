## 模块1 (快速开始与适用场景)

### 1.1 这是什么
一个把“小说创作”拆成可确认、可验收、可迁移流程的 skill：少关键词启动 → 约束清单 → 定调包 → 施工包 → 可执行框架 → 试写 → 正文。

### 1.2 适用场景
- **少关键词创建或完善小说框架**：用户只有零散关键词，想先看到可讨论的初版框架。
- **将零散故事关键词转化为结构化大纲**：用户已有故事想法，需要结构化到可写第一章。
- **确认故事方向与章节构建**：用户需要逐层确认定调包与施工包，避免写到一半返工。
- **继续输出正文各章节内容**：框架与试写确认后，按章节推进正文。
- **一致性管理**：写到一半时检查人物、时间线、伏笔、约束是否冲突。
- **压缩当前 Agent 上下文**：用户说“压缩”时，输出轻量压缩包，以便在当前会话清减上下文后继续写作，不丢失进度、人物状态与未回收伏笔。
- **归档迁移新 Agent**：用户说“归档”时，输出自包含归档包，以便用户新开 Agent 迁移续写，保持框架、进度、状态与风格一致。

### 1.3 不适用场景
- 只要一段即兴短文、不需要框架与验收。
- 要求逐字模仿在世作家独特文风。
- 无文件系统且不接受粘贴模式降级。
- **逆向解构**：不在本 skill 范围，另见独立 skill（待建，低优先级）。

### 1.4 启动方式
| 方式 | 用户说什么 | Agent 做什么 |
|---|---|---|
| 少关键词启动 | 一句题材/设定/人物/冲突，或若干关键词 | 不拒写，出约束清单；用户确认后进定调包，缺失标假设 |
| 模板启动 | “给我模板”“怎么给关键词” | 展示最小输入卡；要更细再给完整模板（见附录B） |
| 模式指令 | 默认正向蓝图；“盲盒连载”仅识别入口 | 正向蓝图走全流程；盲盒待定，不实现、不验收 |

### 1.5 最短使用路径
```text
给关键词 → 确认约束 → 确认定调包 → 确认施工包
→ 可执行框架v1 → 试写开篇 → 确认后写正文
```
每步都可说“修改/回退/查看全量”；细则见模块4—7。

### 1.6 工作区目录一览（入门必读）

```text
novel-project/

  01_anchor.md
  02_state.md
  03_archive.md
  04_compress.md

  framework/characters.md
  style/sample.md
  changelog/changes.md
  versions/

```

| 路径 | 含义 | 默认载入 | 何时读取 | 备注 |
|---|---|---|---|---|
| `00_manifest.md` | 唯一入口索引 | 是 | 每轮必读 | 进度/版本/该读什么 |
| `01_anchor.md` | L0常驻锚点 | 是 | 每轮必读 | 梗概/主角四件套/当前章目标 |
| `02_state.md` | 状态账本+三表 | 是 | 每轮必读 | 人物/时间线/伏笔 |
| `03_archive.md` | 归档包 | 否 | 迁移、查看归档时 | 派生文件 |
| `04_compress.md` | 压缩包 | 否 | 上下文重置恢复时 | 派生文件 |
| `chapters/` | 章节原文 | 否 | 写下一章读最近1章；一致性检查读指定章 | 不默认全读 |

| `framework/characters.md` | 人物档案（每人一张） | 否 | 写任何有人物出场的场景前 | 目的四层/缺陷/冲突/秘密/弧光/写法 |
| `style/sample.md` | 风格样例 | 否 | 试写/续写需要语感时 | 200—300字 |

| `versions/` | 历史版本 | 否 | 用户明确要求复盘旧版 | 存档全保留 |

**总则**：默认只读前三件；其余文件存在但不默认载入，按任务或用户指令读取。读取规则见模块7。

### 1.7 本 skill 不能保证什么（v0.2 新增，能力边界声明）

**这一节比后面所有表格都重要。** 本 skill 保证的是“不出低级错误”，不是“写得好”。

| 能保证（可检查） | 不能保证（靠人与模型） |
|---|---|
| 结构有效：节点齐全、章末有变化、节拍不超编 | 语言辨识度：这个句子只能由这个人说出来 |
| 情节有内在必然性：因果链不断 | 情感真实：读者会不会被触动 |
| 人物有一致性：动机表、知识边界、行为底线 | 人物可信：读者会不会“不同意却相信” |
| 信息出场顺序正确：读者该知道时才让他知道 | 主题深度：不喊口号、呈现复杂性 |
| 细节能承重：每条细节指得出它暴露了什么 | 原创眼光：观察角度、形式、关系的独特性 |
| 一致性：伏笔、时间线、物证、数字 | 多义与重读：第二遍能读出另一层 |
| 节奏的形式面：字数、节拍、章数配比 | 节奏的经验面：哪里该加速、哪里该留白 |

**使用纪律**

1. 任何门禁通过，只代表“这一层的形式要求满足”，**不代表作品成立**。
2. 自检报告里不得出现“可交稿”“已达到标准”一类结论；只写“通过/未过 + 未过项”。
3. 用户或读者指出的问题，优先于本 skill 的任何自检结论。
4. 若条件允许，G3 必须盲读；盲读缺席须在交接单注明（见 6.1.1）。

**一句话**：小说家决定这本书能不能被记住，流程只决定它会不会犯低级错误。

## 模块2 (输入契约)

### 2.1 最小输入
用户至少给以下任意一类即可启动：
- 一句题材/设定/人物/冲突描述；
- “小说家关键词”若干；
- “小说关键词”若干。

不足时不拒写：先出最小必填初版框架，缺失处标“假设”，列入待确认项。**模板是加速器，不是门槛。**

### 2.2 推荐输入（可选）
- 小说家关键词：风格、语言、擅长题材、叙事习惯、禁忌。
- 小说关键词：类型、核心设定、主要人物、核心冲突、主题、氛围、视角、篇幅、必须出现、绝对不能出现、结局倾向。
- 篇幅：短/中/长或预计字数；未给则按复杂度判档并标假设。

### 2.3 模板调起机制
- 默认不展示模板，直接收关键词进入约束解析。
- 仅在两种时机轻提示一次“是否调起推荐模板”：首次使用且输入极少；约束解析后发现核心层关键字段缺失≥3项。
- 用户拒绝后不重复问；同一项目只提示一次。
- 展示分两级：先“最小输入卡”，用户要更细再给“完整推荐模板”。
- 完整模板见附录B。

### 2.4 输入解析输出与约束确认
Agent 收到输入后先输出**约束清单**（格式见4.1）：硬约束、软偏好、禁用项、待确认项、假设清单。冲突优先级：禁用项>硬约束>软偏好>自由发挥。

**约束确认循环 C1（必须停）**：
1. Agent 输出约束清单后必须停，明确说：“请确认约束清单：可增删改；确认后进入定调包。”
2. 用户可多轮增删改；每次修改出4.6变更表，不重贴全表。
3. 用户说“确认/可以/通过”后，才进入 S3 定调包生成。
4. 未确认不得生成定调包；用户说“直接出框架”也须先确认约束清单。
5. C1 不称门禁，避免四门禁变五门禁；但未确认同样不推进。
 . 
### 2.5 来源隔离（v0.2 新增，硬规则）

`来源` 一列只有三个合法值：**用户明示 / 模板填写 / AI推断**。其中“用户明示”只允许来自**当前对话中用户说过的话**。

| 情形 | 处理 |
|---|---|
| 工作区里有现成文件（草稿、旧大纲、笔记） | 默认**不是**输入；须问一句“这个文件算不算本项目的输入”，得到确认后才能写成“用户明示” |
| 用户口头提到但未确认的设定 | 写“AI推断”＋“待确认”，不得写成“用户明示” |
| AI 自己查到的、推导出的 | 一律“AI推断” |
| 发现此前写错了来源 | 立刻出变更表降级（`假设转硬约束`的反向），不得静默保留 |

**为什么要这条**：来源错了，后面所有“必须遵守”都是假的。本项目实测过一次——把工作区 `草稿/` 当作用户明示写进约束，连带三条世界规则、两个人物名、七个禁用项全部污染，事后只能整段降级或删除。

**验收**：约束清单里每一条标“用户明示”的，都要能被指回一句用户原话；指不回的，改标 AI推断。

```text

S0 接收输入

→ C1 约束确认（可多轮增删改）
→ S3 定调包生成 → 定调包初版
→ G1 定调门
→ S4 施工包生成 → 施工包初版
→ G2 施工门
→ S5 可执行框架v1交付（总控台）
→ S6 试写开篇场景 → 试写片段
→ G3 试写门
→ S7 正文生成
→ G4 正文启动
        ↓
   模块7 写作期（三层记忆/章前自检/章后记账/周期校准/压缩归档）

入口B：续写工作流（拿包接着写）
```

**入口选择规则**：
- 用户只给关键词/一句描述 → 默认入口A。

- 入口B不重过 G1—G3；但 R1 接续确认单发现版本不一致、未决A级、关键字段缺失时，须先补包或回退，不得硬写。
- 两条入口在“模块7写作期”汇合，之后机制一致。

## 模块4 (输出契约)

### 4.1 约束清单

**4.1.1 目的与定位**：S2产物，后续所有框架的“约束宪法”；只记约束与处理，不写创作建议。
**4.1.2 输出时机与更新规则**：S2首次全量；G1/G2回退或修改后只出“约束变更表”；用户可要求查看全量。
**4.1.3 字段定义**：固定五列 `类型｜内容｜来源｜影响层级｜处理`。
**4.1.4 枚举与取值**：类型（硬约束/软偏好/禁用项/待确认项/假设）；来源（用户明示/模板填写/AI推断）；影响层级（核心层/人物层/世界层/情节层/章节层/一致性层/全局）；处理（必须遵守/尽量体现/禁止出现/需用户确认/暂按假设执行）。
**4.1.5 处理规则**：可检查；冲突不静默；假设显性；去重合并。
**4.1.6 示例**：
| 类型 | 内容 | 来源 | 影响层级 | 处理 |
|---|---|---|---|---|
| 硬约束 | 记忆可租赁 | 用户明示 | 世界层 | 必须遵守 |
| 软偏好 | 短句冷峻 | 用户明示 | 全局 | 尽量体现 |
| 禁用项 | 不得穿越 | 用户明示 | 全局 | 禁止出现 |
| 假设 | 主角为租赁管理员 | AI推断 | 人物层 | 暂按假设执行 |
| 待确认 | 结局是否开放 | AI推断 | 核心层 | 需用户确认 |
**4.1.7 验收挂钩**：五列齐全、枚举合规、可检查、冲突已标、假设显性；不合格退回S2。

### 4.2 定调包初版

**4.2.1 目的**：S3产物，回答“故事是否成立、人物是否撑得起、世界是否制造压力”。
**4.2.2 时机**：S3首次全量；回退后只出变更表；用户可查全量；标版本号。
**4.2.3 字段**：核心层5项（梗概/核心冲突/主题问题/结局方向/核心卖点）；人物层4项（主角四件套/对手/关键配角/关系网）；世界层4项（背景/关键规则≥2/代价与限制/压力来源）。
**4.2.4 格式**：三层小标题+表格；包末附自检表（检查项/结果/说明）、交接单（类别/内容）、待确认项（编号/问题/影响层级/选项/建议）。
**4.2.5 规则**：少关键词不拒写；不展开施工细节；A级矛盾不静默；每条设定须制造压力；**主要人物须另出人物档案**（见 4.2.8）。

**4.2.6 示例**：见模块9.3与附录B。
**4.2.7 G1验收**：三层最小必填齐全或标假设；主角四件套；对手合理；世界≥2规则制造压力；主题/结局明确；三件套齐全；**主要人物档案齐全（含目的四层与冲突性质）**；**称谓与层级表已建**；无未决A级。

**4.2.8 人物档案（v0.2 新增，定调包附件的独立文件）**

定调包的“人物层”只有四个格子，装不下一个真人。人物档案单独成件（建议 `characters.md`），每人一张，字段如下：

| 项 | 内容 |
|---|---|
| 对外身份 | 别人怎么称呼他 |
| 隐藏身份 | 他自己知道、别人不知道的事 |
| 一句话人设 | 用一个“守／欠／借”的动作概括 |
| 目的 | 外部目标／内部需求／他以为自己要的／他真正要的（四层，缺一不可） |
| 缺陷与代价 | 缺陷是什么、每次都让他付什么 |
| 冲突 | 与谁争什么，并写明冲突**性质**（立场／规则／时间／恐惧／镜像） |
| 秘密 | 他瞒着别人的、别人瞒着他的 |
| 弧光 | 起点→转折（标章）→终点→代价 |
| 写法 | 声音／手／汗／习惯／语言五条可观察特征 |

**关系网**另附一表：`关系｜谁欠谁｜谁控制谁｜谁误解谁`——三列缺一，关系就是平的。

**反派“不洗白条款”（可选，用户要求时写入）**：不给悲情前史；不给“其实为了救人”的动机；恶必须是主动的、精算的；他的手段要能写出一条完整逻辑，但不给读者同情他的出口。

**验收**：每个有名字的人物都有档案；每张档案的“目的”四层齐全；每一对主要关系都能填满三列。

### 4.3 施工包初版

**4.3.1 目的**：S4产物，回答“情节是否升级、章节是否可写、一致性是否可控”。
**4.3.2 时机**：S4首次全量；回退后只出变更表；用户可查全量；标版本号。
**4.3.3 字段**：情节层（节点类型/事件/改变了什么/涉及人物/冲突升级/结局兑现）；章节层（章序/目标/冲突/转折/信息释放/章末变化/伏笔选填/字数/对应节点选填/**节拍数/每节拍字数**）；一致性层（伏笔回收表/时间线/人物一致性/风险清单/**物证与数字表**）。

**节拍配额（v0.2 新增，硬规则）**：一章的“节拍”＝一个独立事件或一次明确转折。
- 单章节拍数 **≤3**；每节拍 **700—1,100 字**。
- 超过 3 个节拍，必须拆章，不得压缩。
- 判定方法：把本章写成一句话，若这句话需要“然后又……然后又……”才算完整，即为多节拍。
- 反例（本项目实测）：3,133 字装 17 个节拍，平均每节拍 184 字，读者反馈“像被灌信息”。

**4.3.4 格式**：三层表格；附件**六件套**顺序：自检表→可写性四问→**行为动机表**→定调包修正建议清单→待确认项→交接单。
**4.3.5 规则**：A级硬停；B/C级包末清算；篇幅适配；伏笔选填；不写正文；一致性前置检查；用户越级不跳G2。
**4.3.6 示例**：见模块9.4与附录B。
**4.3.7 G2验收**：字段完整；可写性四问全“是”；一致性前置通过；**六件套齐全**；**单章节拍数≤3**；**行为动机表每条四列齐全**；**因果链无断链**；无未决A级。

### 4.4 可执行框架v1

**4.4.1 目的**：S5总控台，非合订本；装配、总表、就绪声明、索引。
**4.4.2 时机**：G2通过后输出；变更沿用4.6。
**4.4.3 字段**：装配清单（产物/版本/状态/位置）；总控表（假设/待确认/风险/矛盾清算）；就绪声明；索引表。
**4.4.4 格式**：四张表依次排列。
**4.4.5 规则**：不重贴全文；版本不一致先停；未决A级不进试写；假设显性；只总控不创作。
**4.4.6 示例**：见模块9.4。
**4.4.7 验收**：G2已过；四块齐全；版本一致；无未决A级；就绪声明明确。

### 4.5 试写片段

**4.5.1 目的**：S6唯一含正文片段的输出；验证写法，不替代正文。
**4.5.2 时机**：S6输出开篇第一场景；回退后只出修改说明+重写片段；可标版本B/C。
**4.5.3 字段**：场景卡（目标/视角语气/人物声音/信息释放/结尾钩子/对应章节）；正文片段；一致性检查表；交接单。
**4.5.4 格式**：场景卡→正文片段→一致性检查表→交接单。
**4.5.5 规则**：只写开篇场景；不新增施工包外关键设定；不违反约束；失败不进正文；不计入正式字数。
**4.5.6 示例**：见模块9.5。
**4.5.7 G3验收**：像不像；能不能继续读；有无一致性硬伤。

### 4.6 通用变更表

- 位置：后置4.6，4.1/4.2/4.3只引用。
- 元信息头：项目名/当前版本→新版本/触发原因/变更时间。
- 8列：`变更编号｜变更类型｜涉及层级｜原内容｜变更后内容｜来源/原因｜影响范围｜回退等级｜状态`。
- 规则：只列变更不重贴全量；A级硬停、B/C级包末清算；可追溯；确认后升版本，驳回保留原版并记录。

### 4.7 因果链三段校验（v0.2 新增）

**4.7.1 目的**：把“自洽”升级为“可验”。自洽是作者自己能圆；可验是读者能在前文找到依据。

**4.7.2 时机**：S4；每个“机制类”设定与每个关键行为都必须过一遍。

**4.7.3 格式**：每个设定写三段，缺一段即断链。
```text
因为 A（前文已有的东西）
→ 所以 B（中间的机制或动作）
→ 因此 C（读者看到的结果）
```
**4.7.4 规则**
- 一条设定最多跨 **两步**；跨三步即失效，须拆成两条或删掉一层。
- 任一箭头找不到前文依据，标“断链”，回 S4。
- 允许“读者暂时不知道 A”，但 A 必须在同一章或更早出现过。

**4.7.5 验收**：断链数为 0 才可过 G2。

**4.7.6 反例（本项目实测）**
```text
✗ 她贴一片“恐惧” → 所以能判断对方记忆真假
  断点：贴片只作用于自己，与对方无关；跨了三步（贴片→感知变化→判断能力→结论）
✓ 她贴一片“耐心” → 所以能坐住听完 → 因此听出了矛盾
  每一步都有前文依据：贴片作用域（只对内）、她的缺陷（没耐心）、听力（职业能力）
```

### 4.8 信息出场顺序表（v0.2 新增）

**4.8.1 目的**：读者还不认识这个东西时，不能让它承担专业功能。

**4.8.2 时机**：S4；核心道具、核心机制、核心专名各一张表。

**4.8.3 字段**：`对象｜第 1 次出场只写哪一面｜第 2 次｜第 3 次｜机制是否解释｜首次出现章`

**4.8.4 规则（硬）**
1. **首次出场只用最基础、最好懂的用法**，不给专业功能。
2. 专业用法必须出现在“前置动机”建立之后（例：先让她因不肯用而失败，再让她不得不用）。
3. **机制不解释，只给效果**；必要时用一句“行内老话”带过。
4. 每一章只加一层，不叠加。

**4.8.5 验收**：核心道具的首次出场章，若含专业用法或机制解释，G2 不通过。

**4.8.6 反例（本项目实测）**：核心道具“忆贴”在第一场审讯里就被用来判断真伪，读者连它是什么都还不知道，反馈为“一头雾水”。修正后顺序：第 1 章只用“补”（给自己补情绪）→ 第 2 章才写“办案时也要靠它” → 第 5—6 章才写“黑市以它当货币”。

### 4.9 人物行为双栏检查（v0.2 新增）

**4.9.1 目的**：把“人物可信”从主观感觉变成可判据。

**4.9.2 字段**：`行为｜读者会不会同意（不要求）｜读者会不会理解（必须）｜不理解时缺哪段铺垫`

**4.9.3 规则**
- 同意与理解分开判：读者可以不同意，但必须理解。
- “不理解”即回 S4 补铺垫，或回 4.2 修人物动机。
- 作者为了让情节发生而让角色说的一句话，通常两栏都过不了——这是最该删的句子。

**4.9.4 反例（本项目实测）**：男主初遇女主即承认“那格标签是我撕的”。读者能理解（他确实撕了），但不相信（他不是会说这话的人）。修正为：他只给边界（“仓库不对外”），藏的动作被看见，话没漏。

### 4.10 可删清单（v0.2 新增）

**4.10.1 目的**：好小说多数是改出来的；敢于删掉漂亮但无用的段落。

**4.10.2 时机**：每章完稿后、进入下一章前。

**4.10.3 字段**：`段落/句子｜为什么漂亮｜它推进了什么（事件/关系/信息/人物）｜删或留`

**4.10.4 规则**
- “四推进”一栏填不出来的，**默认删除**。
- 不服的，须写一句保留理由（“它埋了 X 的伏笔”也算，但必须指得出回收章）。
- 每章至少执行一次，结果写进章后记账。

**4.10.5 验收**：连续三章未执行可删清单，视为本章未完成（与 7.5 章后记账同等级）。

## 模块5 (分层框架规范)

### 5.1 分层总则
- 6层关系：前3层定方向，后3层定施工；上层未确认不展开下层。
- 层间契约：每层末尾输出“本层为下一层提供的输入清单”，三列 `输入项｜来源层字段｜下层用途`。
- 回退触发：A级硬停；B/C级标假设或待确认，包末清算；回退标“回退点：第X层某设定”。
- 与模块4分工：模块4写产物字段，模块5写“每层怎么写才合格”，字段只引用不重列。
- 五段式：层目标、最小必填、扩展字段、可检查标准、常见错误。

### 5.2 核心层
层目标：明确“什么故事、为什么值得看、走向哪”。最小必填引用4.2.3。扩展：中篇加故事承诺；长篇加卖点排序、主题副问题。可检查：梗概含主角/欲望/阻碍/代价；冲突一句话；主题是问题；结局方向明确；卖点可区分。常见错误：背景介绍当梗概；主题说教；结局写成具体情节；卖点空泛。

### 5.3 人物层
层目标：谁推动故事、想要什么怕什么、最后变成谁。最小必填引用4.2.3。扩展：中篇加人物弧光表；长篇加语言习惯、知识边界、关系网图、功能标签。可检查：主角四件套；对手合理阻挡；配角有功能；关系网有张力；每人能答“想要/害怕”。常见错误：人物简历；对手为坏而坏；配角凑数；关系网只有名字；弧光空话。

### 5.4 世界层
层目标：什么规则制造压力、代价是什么、如何逼人选择。最小必填引用4.2.3。扩展：中篇加社会结构、设定一致性清单；长篇加规则历史成因、规则冲突矩阵、阶层影响。可检查：≥2规则制造压力；有违反代价；逼出关键选择；背景影响行动；规则无未标矛盾。常见错误：百科介绍；规则不产生冲突；无代价；空词代替规则。

**命名纪律（v0.2 新增）**

| 项 | 规则 |
|---|---|
| 专名表 | 每个自造专名一行：`名字｜含义｜首次出现章｜句内是否自解释｜是否承担双重功能` |
| 见名知意 | 读者第一次看到这个词，不需要停下来查；能用两个常见字拼出来，就不用生造词 |
| 一名字一功能 | 一个词只承担一件事；商品名、品类名、行话名可以分层，但不能互相顶替 |
| 首次自解释 | 专名第一次出现时，必须在同一句或相邻句里露出它“是什么形态、干什么用” |
| 禁止 | 为求酷而造词；用生造词代替解释；同一层里出现两套叫法 |

反例（本项目实测）：“接驳片”——读者无法建立图像；“渠”——作者自己懂，读者不懂。修正：“忆贴”（忆＋贴，见名知意）、“货路”（黑市上游，可自解释）。

**称谓与层级表（v0.2 新增）**

世界的机构、角色、商品必须各有一套叫法，不得混用。

| 层 | 只允许一套叫法 | 禁止 |
|---|---|---|
| 官方机构 | 一个名字，全篇不变 | 同一机构出现两个称呼 |
| 商业门店 | 品牌名＋门店号（如“忆栈·007 站”） | 把门店叫成机构 |
| 民间／行内 | 行话一套（如“站”“货路”） | 把行话写进公文 |
| 商品 | 商品名＋品类名＋黑市版，三层分开 | 同一件货出现两种同名 |

校验：出现在正文里的每个机构名，都要能在称谓表里找到唯一对应项；找不到即标错，回 S4。

反例（本项目实测）：“管理局”“站点”“警局”三层混用，改了三次才分清。

### 5.5 情节层
层目标：怎么升级、每节点改变什么、结局如何兑现。最小必填引用4.3.3。扩展：短篇3—5节点；中篇六类齐全；长篇加情绪曲线、冲突升级表、多线汇合点、误导线索表。可检查：六类节点齐全或说明；改变落在局势/认知/关系/风险；升级≥3级；结局兑现三项；人物在人物层存在。常见错误：流水账；改变空话；换对手当升级；结局只写外部；人物凭空出现。

### 5.6 章节层
层目标：每章谁想干什么、被什么挡、章末变化，能否落笔。最小必填引用4.3.3。扩展：短篇场景表3—5；中篇章节表8—15；长篇卷—章—场景三级+多线汇合点+节奏风险表。可检查：每章三问；章末变化至少一项；对应情节节点；伏笔无写“无”；字数有预估；短中长篇数合规。常见错误：目录式章表；章末无变化；每章埋伏笔；中篇膨胀；长篇无卷目标；伏笔留空。

### 5.7 一致性层
层目标：有没有埋了不收、说了不算、前后矛盾。最小必填引用4.3.3。扩展：短篇伏笔简表+时间线+人物一句；中篇**五表齐全**；长篇加多线汇合表、节奏风险表、误导线索表、伏笔状态列。可检查：伏笔有回收或说明；时间线顺序无矛盾；人物三边界；风险覆盖四类；**物证与数字全篇一致**；长篇多线标汇合。常见错误：只埋不收；时间只写“后来”；人物写形容词；风险不标层级；多线断头；不回收不说明；**编号/年龄/数量前后不一**。

**物证与数字表（v0.2 新增，第五表）**

| 字段 | 内容 |
|---|---|
| 物证／数字 | 编号、年龄、日期、金额、数量、距离、次数 |
| 首次出现 | 第几章，原文怎么写 |
| 后续每次出现 | 逐个列出章号与写法 |
| 是否一致 | 一致／需修正 |

规则：**同一数字只要被读者记住过一次，就必须全篇一致**；数字与形态必须对齐（例：“只剩两个数字”就不能写出四位数编号）；编号中的每一段要有明确含义（站号／库位／年份），不得临时编造。

反例（本项目实测）：标签写“只剩两个数字”却给出 0713；“前两位是站号 07”却走进 003 站；34 岁的人“记得自己七岁”与“二十七年前”未对齐。

### 5.8 扩展字段矩阵
| 层 | 短篇（≤1.5万字） | 中篇（1.5—8万字） | 长篇（>8万字） |
|---|---|---|---|
| 核心层 | — | 故事承诺 | 卖点排序、主题副问题 |
| 人物层 | —（≤5人） | 人物弧光表 | 弧光表+语言习惯+知识边界+关系网图+功能标签 |
| 世界层 | —（2规则+压力） | 社会结构、设定一致性清单 | 加规则历史成因、规则冲突矩阵、阶层影响 |
| 情节层 | 3—5节点（可合并说明） | 六类齐全 | 加情绪曲线、冲突升级表、多线汇合点、误导线索表 |
| 章节层 | 场景表3—5 | 章节表8—15 | 卷—章—场景三级；多线汇合点、节奏风险表 |
| 一致性层 | 伏笔简表+时间线+人物一句 | 四表齐全；伏笔加表面/真实含义 | 加多线汇合表、节奏风险表、误导线索表；伏笔加状态 |

启用规则：最小必填永远必填；复杂度可覆盖字数；启用扩展须自检；未启用不视为缺失，启用但空视为不合格。升降档走4.6变更表。

**篇幅—章数—节拍换算表（v0.2 新增）**

先定总字数，再定每章节拍数，章数自然出来；**不要先定章数**。

| 计划总字数 | 每章 2—3 节拍 × 700—1,100 字 | 合理章数 | 篇型 |
|---|---|---|---|
| 1.5 万 | 约 2,000／章 | 7—8 章 | 短篇 |
| 3 万 | 约 2,200／章 | 13—14 章 | 中篇 |
| 4.5 万 | 约 2,300／章 | 18—20 章 | 中篇加长 |
| 10 万 | 约 2,300／章 | 42—45 章 | 长篇 |
| 14 万 | 约 2,300／章 | 60—65 章 | 长篇 |

反例（本项目实测）：4 万字切成 65 章＝每章约 600 字，节拍密度不变，节奏只会更碎。**章数不是节奏的解药，节拍数才是。**

章数定了之后，再核对两件事：①配角人数是否够填（每 10 章约需 2 个有名字的功能人物）；②支线是否够撑（每 20 章约需 1 条支线）。不够就必须减章或加人物，二者不可只取其一。

## 模块6 (确认、验收与回退)

### 6.1 门禁总表
| 门禁 | 检查对象 | 前置 | 通过条件（摘要） | 未过处理 | 记录 | 细则 |

| G2 | 施工包初版 | G1已过 | 六节点+改变；章节字段；**单章节拍数≤3**；**因果链无断链**；**行为动机表齐全**；**核心道具首次出场只用基础用法**；伏笔可回收；一致性前置（含物证与数字表）；**六件套齐全**；无未决A级 | 按6.2.3回S4/S2/G1 | 施工包交接单 | 4.3.7、4.7、4.8、4.9、6.2.3 |

| G4 | 是否开写正文 | G3已过 | 用户明确“开始写正文” | 按6.2.5停S6后或回G3/S5 | 4.4状态栏 | 6.2.5、6.3 |

通用规则：门禁独立；未过不推进；记录可追溯；细则不重列。

**6.1.1 盲读验收（v0.2 新增，接在 G3）**

自检能验形式，验不了好看。凡有条件，G3 必须找**没读过大纲的人**读一遍，问三问：

| 问 | 合格标准 |
|---|---|
| 他是谁？ | 能说出这个人此刻的处境与想要什么 |
| 他为什么这么做？ | 能自己讲出因果，而不是“作者让他这么做” |
| 想不想读下一章？ | 想，且能说出为什么想 |

无人可读时，允许退化为自问，但必须在交接单注明“盲读缺席”，并把该风险带入 G4。

依据（本项目实测）：我每一版自检都“通过”，3 位试读者一读就指出节奏过载——自检与读者之间隔着一条经验层的沟。

1. 缺项先补，不默认通过。

5. 越级指令先补门禁；用户二次确认后才可例外，记录“用户越级授权”。

### 6.5 验收记录与版本

**6.5.1 记录字段**：门禁编号与名称；检查对象及版本；未过项与回退点；用户指令原文；验收时间；验收结论。
**6.5.2 版本号规则**：产物独立版本；初始v1；内容变更升次版本；A级重写升主版本；驳回不升版本；版本号出现在标题行与交接单。
**6.5.3 存储与载入策略**：版本存档全保留于工作区；每轮上下文只载入当前有效版本、最近变更摘要、未决待确认项；历史版本不默认载入，按需召回；有工作区时以manifest为载入索引。
**6.5.4 与4.6衔接**：每次版本变更对应4.6记录；交接单只写“基于vX；变更见C1、C2”；4.4装配清单须列当前版本。
**6.5.5 记录查看与跨会话续写**：记录随交接单保存；用户说“查看验收记录/版本历史”时输出各产物版本+最近门禁结果+变更编号索引；跨会话以manifest/总控台为版本基准。

## 模块7 (正文写作与上下文管理)

### 7.1 目的与原则
token可控、一致性优先、存档与载入分离；正文期不重载全文框架。

### 7.2 读取规则与任务映射

**7.2.1 默认载入**：每轮只读 `00_manifest.md` + `01_anchor.md` + `02_state.md`。文件含义见模块1的1.6。

**7.2.2 任务—载入映射**
| 任务 | 默认载入 | 追加载入 |
|---|---|---|
| 续写下一章 | manifest+anchor+state | 当前章施工卡、最近1章原文 |
| 写正文中某场景 | manifest+anchor+state | 本章施工卡、上一场景原文 |
| 一致性检查 | manifest+anchor+state | 按manifest指引读伏笔表/时间线/人物表或相关章节 |
| 复盘/对比旧版 | manifest | 指定历史版本文件 |
| 压缩 | manifest+anchor+state | 最近3章摘要（state已有则不追加） |
| 归档 | manifest+anchor+state+framework摘要 | 风格样例、变更摘要 |
| 新agent接续 | manifest+archive | 按接续确认单再读state/chapters |

**7.2.3 载入纪律**：默认三件套+按任务追加；不默认读全章节、不默认读历史版本；压缩包/归档包为派生文件，不进入默认载入。

### 7.3 三层记忆
- L0常驻锚点：梗概、主角四件套、世界2规则、当前章目标、未回收伏笔编号。
- L1滚动摘要+状态账本：章级摘要、人物位置状态、时间线、伏笔状态。
- L2按需召回：人物卡、伏笔表、旧章节原文。

### 7.4 章前自检
锚点+上一章结尾+本章施工卡三对照，确认人物状态/时间/伏笔无冲突。

### 7.5 章后记账
更新章摘要、状态账本、伏笔状态；不记账视为本章未完成。

**v0.2 增补**：章后记账还须包含两项——①**节拍核对**：实际写了几个节拍，是否超过 3 个；超了就在下一章拆章，不得靠压字数过关。②**可删清单**：本章标出“漂亮但无用”的段落并处理（见 4.10）。两项缺一，同样视为本章未完成。

### 7.6 周期校准
每3—5章一次；长篇每卷末强制。

### 7.7 长篇压缩策略
最近3章摘要+卷级摘要+状态账本；旧章摘要压缩为卷级一句话。

### 7.8 压缩与归档指令

**7.8.1 触发与三档产物**

用户说“压缩”：生成 `04_compress.md`，用于当前会话减负，不迁移。

用户说“归档”：按三档处理。

| 档位 | 输入指令 | Agent操作 | 用户操作 | 新agent读取 |
|---|---|---|---|---|
| 档1 最小可续写包（默认） | “归档” | 写 `03_archive.md`，自包含：元信息、约束摘要、定调摘要、进度与施工索引、状态三表、当前章卡、最近1章摘要、风格样例、框架索引、变更摘要、启动指令；更新manifest | 只拿 `03_archive.md` 一个文件，放到新agent工作区或直接粘贴 | 读 `03_archive.md` → 出接续确认单 → 用户确认 → 续写；缺关键信息先要求补包 |
| 档2 最小包+原文附件 | “归档，带第X章” | 写 `03_archive.md`（同档1）；复制指定章节到 `archive_attachments/`；归档包内只放索引表；更新manifest | 拿 `03_archive.md` + `archive_attachments/` 整个目录 | 读 `03_archive.md`；需要语感或一致性检查时按索引读对应章节 |
| 档3 完整工作区迁移 | “打包工作区/完整迁移” | 生成 `archive_bundle.zip`，内含 manifest、anchor、state、archive、chapters、framework、style、changelog、附件（如有）；更新manifest | 拿整个zip，解压到新环境工作区 | 按正常续写入口：读manifest+archive → R1接续确认单 → 续写；后续按7.2读取 |

说明：默认档1；三档均更新manifest，记录归档位置、档位、生成时间；档1须自包含到“只读此文件即可出接续确认单”，缺字段按7.9.4补包。

**7.8.2 压缩包字段（1500—3000字）**
| 字段 | 内容 |
|---|---|
| 项目标识 | 项目名+进度（第X章/共Y章；当前卷） |

**7.8.3 归档包字段（5000—8000字，自包含）**
| 字段 | 内容 |
|---|---|
| 元信息 | 项目名、类型、篇幅、视角、当前版本与门禁状态 |

3. 生成后更新 `00_manifest.md`（字段见B5.1）的“压缩包/归档包位置、档位、生成时间”。

### 7.9 续写工作流与接续协议

**7.9.1 独立入口**：续写为独立入口，与正向构建并列；仅在用户明确说“续写/接着写/从归档继续/开始续写”时触发。用户只给关键词时默认正向构建。

**7.9.2 续写工作流 R0—R3**
```text
R0 读取 00_manifest.md + 03_archive.md
→ R1 输出接续确认单
→ R2 用户确认
→ R3 进入模块7写作期（章前自检→写→章后记账）
```
| 状态 | 动作 | 输出 | 停止点 |
|---|---|---|---|
| R0 | 读 manifest+archive | 项目状态摘要 | 无 |
| R1 | 生成接续确认单 | 接续确认单 | 停，等用户确认 |
| R2 | 用户确认 | 确认记录 | 未确认不续写 |
| R3 | 进入写作期 | 正文 | 每章仍走7.4/7.5 |

**7.9.3 接续确认单字段**
| 字段 | 内容 |
|---|---|
| 当前进度 | 已写到第X章/共Y章；当前卷/阶段 |
| 下一章目标 | 谁想干什么、冲突、章末变化 |

| 人物状态 | 主要人物当前位置/关系/知识边界 |

| 续写建议 | 建议先写哪章/先补哪项 |

**7.9.4 异常处理**
1. 版本不一致、未决A级、关键字段缺失：先补包或回退，不得硬写；归档包缺关键字段时，新agent须要求补包，不得编造。
2. 读取细节按7.8.1三档表执行；续写不重过G1—G3，但上述异常检查等效于轻量门禁。

### 7.10 一致性风险与处理

**7.10.1 风险来源分类**
| 类型 | 表现 |
|---|---|
| 约束违反 | 出现禁用项、违反硬约束 |
| 人物不一致 | 语言/行为/知识边界漂移 |
| 时间线冲突 | 事件顺序矛盾、相对时间错乱 |
| 伏笔断头 | 埋了不收、回收无铺垫 |
| 风格漂移 | 偏离风格样例 |
